# Локальный ML-модуль Forte Vision

Модель использует пиксели и временные метки кадров. Имя файла, Excel, комментарии,
статусы разметки и источники правил не входят во входные признаки. Звук и
идентификация лиц не используются. Видео, кадры и описания сцен не отправляются
внешним AI-сервисам.

## Запуск

Выполняйте команды из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1
```

Текущее окружение: Windows, Python 3.12, PyTorch 2.7.1/CUDA 12.8, RTX 5070.
Для CPU добавьте `-Cpu` к команде установки. Корневые скрипты создают `.venv`.
Параметр `ExecutionPolicy Bypass` действует только в данном процессе PowerShell.
Старый `ml/requirements-lock.txt` с CUDA 11.8 описывает прежнее окружение и
не является инструкцией установки на RTX 5070. Для macOS/Linux используются
корневые `requirements-dev.txt` и `requirements-ml.txt`.

По умолчанию сервер использует `ml/weights/event_localizer_detector.pt`.
Для локального вызова без HTTP этот checkpoint можно указать явно:

```powershell
.\.venv\Scripts\python.exe ml/main.py predict --video "C:\local-data\new.mov" --checkpoint ml/weights/event_localizer_detector.pt --output data/result.json
```

JSON с JPEG/base64 сохраняется только локально. Не публикуйте его вместе с видео.
Ошибка декодирования или модели завершает обработку ошибкой, а не вердиктом
`no_violation`. После установки зависимостей и весов инференс не скачивает модель.

## Поставляемые модели

- `weights/event_localizer_detector.pt`: текущая модель по умолчанию, формат 4;
  обученный локализатор центров событий и 16 типов действий. Параметры и классы
  сохранены внутри checkpoint: [event_localizer_config.json](weights/event_localizer_config.json).
- `weights/hard_negative_detector.pt`: предыдущая модель после дообучения
  на сложных отрицательных примерах; источник замороженных весов новой версии.
- `weights/reviewed_detector.pt`: предыдущая семантическая модель, сохранённая
  для сравнения и воспроизводимости исторических отчётов.
- `weights/detector.pt`: прежний бинарный baseline с усреднением признаков кадров.
- `weights/temporal_candidate.pt`: прежний бинарный temporal-эксперимент.

Новая модель использует локальный MobileNetV3 Small, головы бинарной
и многоклассовой классификации и отдельную временную голову локализации.
При инференсе `pretrained=False`: внешнее хранилище
весов не используется. Лицензии: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
Происхождение старого baseline сохранено в [SOURCE.json](SOURCE.json).
Показатели старых бинарных экспериментов не описывают новую модель.

## Данные и границы проверки

Объединённая книга содержит 42 файла и 40 уникальных SHA-256: 21 положительное,
19 отрицательных видео, 22 точечных события. Пользователь подтвердил H/J как
окончательные человеческие описания действий в текущем разговоре. Это отдельная
проверка от старых статусов E и бинарных `label_verified`: часть бинарных меток
и таймкодов сохранена из исходной разметки и остаётся слабой.

Импорт в `cashwatch/reviewed_data.py` сохраняет происхождение каждой метки,
координаты H/J и SHA-256 книги. Точные копии имеют один вес и одну часть выборки.
Различные подтверждённые действия в копиях одного видео сохраняются отдельными
событиями. Текст H/J — целевая разметка и provenance, а не признаки модели.

Классы определены в `ACTION_TYPES`. У большинства типов всего один пример;
такие типы остаются в train и не имеют отдельной проверки обобщения.
Диагностический holdout охватывает только часть типов. Связи между сессиями съёмки
и пересечение с прежним обучением не установлены, поэтому результат нельзя
называть независимой оценкой качества. Новый ракурс камеры отдельно не проверен.
Score типа не калиброван и не является вероятностью нарушения.

### Текущие веса: проверка 18.10.2026

`event_localizer_detector.pt` содержит уточнённый локализатор с 599 201 обучаемым
параметром: суммарно 27 эпох и 540 обновлений. Последний этап — 2 эпохи / 40
обновлений с learning rate 1e-5, повторением всех 40 видео и отбором ошибочных
внецентровых срабатываний по выходам модели. Изменены только 6 тензоров
локализатора. Все 256 исходных тензоров энкодера, нормализации, бинарной головы
и головы типов из `hard_negative_detector.pt` побитно сохранены.
Цель — Gaussian-близость к размеченному центру события (σ=0,75 с), а не бинарная
«норма / нарушение». Низкий score локализатора не доказывает нормальность кадра.
При инференсе используется его score с бинарным gate ≥0,5; порог событий 0,5
и постобработка `adjacent_2`, merge gap 1 с сохранены. Вход — только визуальные
признаки и их временные разности; имена файлов и разметка не используются.

Все 42 файла заново обработаны полным `VideoAnalyzer`: декодирование, модель,
JPEG. Успешно 42/42, суммарное время анализа 18,328 с. Этот прямой прогон
не включает HTTP-загрузку, очередь и polling. Основные метрики учитывают
40 уникальных видео и 22 размеченных события, основной допуск — **±1 с**:

| Проверка | Результат |
| :--- | :--- |
| Бинарный итог | TP=21, FP=0, FN=0, TN=19; accuracy и video F1 = 100% |
| Полностью верные видео при ±1 с | 40/40 (100%): 21/21 положительных и 19/19 отрицательных |
| Правильный тип и время ±1 с | TP=22, FP=0, FN=0; precision, recall и F1 = 100% |
| Временные ошибки 22 совпавших событий | Все 0 с относительно имеющейся разметки |
| Остаточные расхождения | Нет относительно имеющейся разметки; лишнее событие Х-13, 58 с, устранено |

«Полностью верно» означает правильный итог, все события с правильным типом
и временем в допуске, без лишних сигналов. Это доля видео, не event accuracy.
Сравнение выполнено с предыдущим локализатором `fd0cb996…`, а не только
с исходным hard-negative checkpoint. Сохранены все 22 прежних верных события
при ±1 с и их нулевые ошибки времени, 39 полностью верных видео и 40 бинарных
решений. Пороги и постобработка не менялись. Исторические проверки относительно
hard-negative версии сохранены в отчёте. При ±5 с также TP=22, FP=0, FN=0.
В Х-13 осталось событие на 47 с; срабатывание на 58 с после обучения не
подтверждается неизменным правилом `adjacent_2`. Отдельный score на 58 с
остаётся около 0,57956; соседние окна больше не подтверждают событие.

SHA-256 текущего checkpoint:
`a56956172d00c5ad4d1e2e4fe2442121e2c711e18b6c5cfe7ee0866ec71e7546`.

Все видео использовались при обучении и выборе весов. Независимая точность на
новых съёмках не установлена. Лишние сигналы — события без совпадающей отметки
в имеющейся разметке; они требуют просмотра, поскольку точечная разметка
может не перечислять все действия. Подробности, SHA-256 и результаты по файлам:
[текущий JSON-отчёт](weights/event_localizer_report.json),
[PDF со всеми событиями и таймкодами](../docs/reports/forte-vision-ml-audit-localizer-refinement-2026-10-18.pdf).

### Исторические эксперименты

Первый локализатор (`fd0cb996…`, 25 эпох / 500 обновлений) давал TP=22, FP=1,
FN=0 при ±1 с: precision 95,7%, recall 100%, F1 97,8%; полностью верны 39/40
видео. Единственный лишний сигнал — Х-13, 58 с. Эта версия является `before`
в текущем отчёте. [Исторический PDF](../docs/reports/forte-vision-ml-audit-one-second-2026-10-18.pdf)
сохранён и не описывает текущие веса.

Предыдущий `hard_negative_detector.pt` дообучал бинарную временную голову
`reviewed_detector.pt` при замороженных энкодере, нормализации и голове типов.
Его precision / recall / F1 событий: **70,4% / 86,4% / 77,6% при ±1 с**
(TP=19, FP=8, FN=3), **74,1% / 90,9% / 81,6% при ±5 с** (TP=20, FP=7, FN=2).
Бинарные решения верны на 40/40 видео, полностью верны 33/40 при ±5 с.
Средняя временная ошибка 0,64 с учитывала только 21 временное совпадение;
сдвиг Х-13 с 47 до 58,5 с в неё не входил. Источник:
[исторический hard-negative отчёт](weights/hard_negative_report.json).

Первый диагностический запуск (28 train / 6 dev / 6 test) дал полный typed F1=0
на dev и test: все три отрицательных видео каждой части ошибочно положительные,
а типы верны в 0/3 размеченных центров. Checkpoint и порог выбирались по dev.
Последующий полный fit `reviewed_detector.pt` после 60 фиксированных эпох
на всех 40 видео имел TP=21, FP=8, FN=0, TN=11, video F1=0,84;
полный event/type F1=0,667 при допуске ±5 с на обучающем наборе.
Эти результаты относятся к прежним весам:
[исторический отчёт reviewed](weights/reviewed_report.json),
[историческая диагностика dev/test](weights/reviewed_diagnostic_report.json).

## Повторение уточнения локализатора

[tools/refine_event_localizer.py](tools/refine_event_localizer.py) воспроизводит
последний этап. Нужны локальный кэш признаков всех 40 видео и сохранённые
checkpoint / отчёт предыдущей версии `fd0cb996…`; скрипт проверяет их соответствие
и происхождение разметки. Эти обучающие файлы не входят в runtime-поставку.
Используйте новый каталог результата; опубликованные веса не заменяются автоматически:

```powershell
.\.venv\Scripts\python.exe ml/tools/refine_event_localizer.py --checkpoint C:/local-data/baseline/event_localizer_detector.pt --before-report C:/local-data/baseline/event_localizer_report.json --features C:/local-data/features.pt --output-dir data/localizer-refinement-new --epochs 2 --learning-rate 1e-5 --device cuda
```

Подбор и проверки сохранения результатов используют тот же обучающий набор.
Перед заменой весов отдельно выполните свежий анализ исходных видео; согласие
с обучающим кэшем не заменяет эту проверку или независимую оценку новых съёмок.

## Повторение подготовки и исходного обучения reviewed

Команды ниже воспроизводят этап до дообучения на сложных отрицательных примерах;
они не создают автоматически текущий `event_localizer_detector.pt`.

Команды выполняются из корня checkout после установки зависимостей. Подставьте
локальные пути к книге и видео. Используйте новые каталоги output для каждого
эксперимента, сохраняя прежние manifest, веса и отчёты:

```powershell
.\.venv\Scripts\python.exe ml/main.py prepare-reviewed --workbook "C:/local-data/dataset_review_merged_ml.xlsx" --videos "C:/local-data/videos" --output data/reviewed-new --confirm-action-notes --allow-weak-original
.\.venv\Scripts\python.exe ml/main.py init-weights --output data/reviewed-new/pretrained/encoder.pt
.\.venv\Scripts\python.exe -m ml.cashwatch.train_reviewed --manifest data/reviewed-new/manifest.json --output ml/artifacts/reviewed-new --encoder-weights data/reviewed-new/pretrained/encoder.pt --epochs 60 --device cuda
```

`--confirm-action-notes` явно подтверждает H/J как окончательные человеческие метки
действий. `--allow-weak-original` сохраняет слабое происхождение исходных бинарных
меток и не делает их проверенными. `init-weights` однократно скачивает начальные
веса энкодера; последующее обучение и инференс используют локальные файлы.
MobileNetV3 Small заморожен: обучаются бинарная и многоклассовая головы.
Для CPU замените `--device cuda` на `--device cpu`.

Подготовка фиксирует диагностическое разбиение train/dev/test; первый запуск
обучения использует его. Для отдельного фиксированного fit на всех 40 уникальных
видео используйте другой output:

```powershell
.\.venv\Scripts\python.exe -m ml.cashwatch.train_reviewed --manifest data/reviewed-new/manifest.json --output ml/artifacts/reviewed-new-full --encoder-weights data/reviewed-new/pretrained/encoder.pt --epochs 60 --device cuda --refit-all
```

`--refit-all` объединяет части для обучения; его метрики описывают только
обучающий набор. Он не добавляет независимого теста. Новые эксперименты
не заменяют поставляемые веса автоматически.

## Ответ и нормативы

```python
from pathlib import Path
from ml.cashwatch.inference import VideoAnalyzer

analyzer = VideoAnalyzer(checkpoint=Path("ml/weights/event_localizer_detector.pt"))
result, diagnostics = analyzer.analyze(Path("C:/local-data/new.mov"), timeout_sec=240)
```

`result` содержит `verdict` и `violations`. У события обязательны `type`,
`timecode_sec`, `description`, 1–3 `evidence_frames` с JPEG/base64 и `rule_source`.
`type_id`, `type_confidence`, `description_source` и `rule_context` поясняют
предсказание. Описание по предполагаемому классу маркируется `class_template`;
исходные человеческие заметки не выдаются за наблюдения модели.

`cashwatch/rules.json` содержит 16 типов, 17 проверенных ссылок на пункты трёх
действующих официальных документов НБРК/АРРФР, дату проверки и ограничения применимости.
Для восьми типов предусмотрено условное публичное основание. Ещё шесть требуют
внутренних правил банка, два — дополнительного контекста; для них остаётся
`status=unmapped` с причиной. Контекстные ссылки не превращаются в прямой запрет.
Бинарный или неизвестный тип не получает выдуманного правила.

При выводе по кадрам нельзя установить суммы, внутренние проводки, подлинность
банкнот, полномочия человека или отсутствие цифровой идентификации только по
внешнему виду. Источник подтверждает текст правила, а применимость проверяет человек.

## Время, очередь и передача

Сэмплирование по умолчанию — 2 кадра/с и окно из 8 кадров. Локализатор учится
выбирать центр размеченного события; ответ содержит PTS выбранного исходного
кадра. Начало и конец события отдельно не размечены. Короткие события могут
попадать между выборками.

Backend уже вызывает локальную модель в отдельном процессе задачи. Общий бюджет
по умолчанию 270 секунд включает multipart-загрузку, проверку файла, очередь,
загрузку весов и анализ; настройка ограничена 290 секундами. Ошибки и таймауты дают
`failed`. Диагностика модели и полное HTTP-время — разные величины.

Подробный контракт и проверка передачи: [HANDOFF.md](HANDOFF.md),
[../docs/model-integration.md](../docs/model-integration.md).
Текущие веса проверены 18.10.2026 прямым полным `VideoAnalyzer` на Windows/Python
3.12/CUDA: 42 файла, 18,328 с суммарного анализа с JPEG.
Источник — [event_localizer_report.json](weights/event_localizer_report.json).
После установки уточнённых весов прошли 130 тестов и 15 подслучаев за 48,09 с,
а также 6 HTTP-проверок: схемы, JPEG и совпадение с прямым анализом валидны.
На Х-13 API вернул ровно одно событие на 47 с. Поля `repository_validation`
и `http_smoke_validation` содержат результаты; этот набор из 6 проверок
не является полным HTTP-прогоном всех 42 файлов.
Исторический HTTP-прогон `hard_negative_detector.pt`: 42 файла, 298,625 с суммарно,
7,097 с в среднем на файл (6,016–13,125 с), включая загрузку, очередь и polling.
Эти HTTP-замеры не относятся к новой версии:
[hard_negative_report.json](weights/hard_negative_report.json).
Проверки изолированного WSL и публичного HTTPS от 17.10.2026 относятся
к прежнему `reviewed_detector.pt`, не к текущим весам:
[исторический технический отчёт](weights/reviewed_runtime_checks.json).
Исходные видео, Excel, обучающие кэши и локальные результаты находятся вне Git.
Для переноса инференса они не нужны. Автономная установка требует заранее
подготовленных wheels для целевой ОС; прежний cu118 lock не является переносимым
wheelhouse. Изоляцию на уровне ОС и доступность публичного URL проверяют отдельно.
