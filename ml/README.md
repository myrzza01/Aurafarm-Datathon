# Локальный ML-модуль — участник 3

Обученный бинарный детектор подозрительных фрагментов видео. Инференс использует
пиксели, локальные веса и временные метки кадров; Excel, имя файла и разметка
в признаки не входят. Видео, кадры и описания сцен внешним AI-сервисам не отправляются.
Звук и идентификация лиц не используются.

В репозитории находятся код подготовки/обучения/оценки, тесты, зависимости,
лицензии и два обученных checkpoint. Исходные видео, Excel, кэши и полные локальные
отчёты экспериментов в Git не включены.

## Быстрый запуск

Проверенное окружение: Windows, Python 3.12, RTX 3050 Ti Laptop 4 GB. Lockfile
фиксирует использованные Windows/PyTorch CUDA 11.8 зависимости; перенос на Linux
нужно проверить отдельно. Выполняйте команды из `ml/`:

```powershell
cd ml
.\setup.ps1
.\.venv\Scripts\python.exe main.py predict --video "C:\local-data\new.mov" --output artifacts/result.json
```

При установке зависимости скачиваются. После установки инференс работает локально
и не загружает модель из интернета. Веса baseline уже лежат в `weights/detector.pt`
и выбираются по умолчанию независимо от текущего рабочего каталога.

Отдельный запуск временной модели:

```powershell
.\.venv\Scripts\python.exe main.py predict --video "C:\local-data\new.mov" --checkpoint weights/temporal_candidate.pt --output artifacts/temporal_result.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Результат с JPEG/base64 пишется только в локальный файл; консоль показывает
технические агрегаты. Ошибка декодирования или модели завершает команду с ошибкой,
а не результатом «нарушений нет».

## Подключение к backend участника 4

Из корня командного репозитория:

```python
from ml.cashwatch.inference import VideoAnalyzer

analyzer = VideoAnalyzer()  # Загружать один раз на worker; baseline по умолчанию.
result, diagnostics = analyzer.analyze(local_video_path, timeout_sec=240)
```

`result` содержит `verdict` и `violations`; у события `type`, `timecode_sec`,
`description`, 1–3 `evidence_frames` с `timestamp_sec` и JPEG `image_base64`.
В `backend/analyzer.py` результат можно проверить через
`AnalysisResult.model_validate(result)`. Модель должна выполняться в отдельном
worker последовательно; один экземпляр не следует одновременно вызывать из
нескольких запросов. Сохраняйте технические исключения как `status=failed`.

Backend уже содержит точки `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}`
с `X-API-Key`. Эта ветка добавляет ML-модуль; подключение обработчика, очередь и
общий таймаут 300 с остаются задачей интеграции. Пример не заменяет обработку
зависшего нативного декодера таймаутом worker-процесса.

Подробные инструкции передачи, HTTP-замера и проверки Windows Firewall:
[HANDOFF.md](HANDOFF.md). Для полностью изолированной установки заранее подготовьте
wheelhouse для целевой ОС. Блокировка исходящей сети на уровне ОС пока не проверена:
доступная сессия не имела административных прав. Python socket guard этого не заменяет.

## Поставляемые модели и измеренные ограничения

- `weights/detector.pt`, `weights/config.json`: сохранённый baseline, усреднение
  признаков 8 кадров. Это текущий вариант по умолчанию.
- `weights/temporal_candidate.pt`, `weights/temporal_candidate.json`: отдельная
  временная сеть, экспериментальный seed 42. Автоматической замены baseline нет.

Предобученный энкодер MobileNetV3 Small имеет 1 517 856 замороженных параметров.
Обучается 3 073 параметра усредняющей головы либо 601 249 параметров временной
Conv1D-головы. Loss: BCEWithLogitsLoss; AdamW. Лицензия и источник:
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

Локальный расширенный набор: 17 видео, 11 train, прежние 2 dev, 4 зарезервированных
test. Происхождение связанных записей ещё проверяется, test-качество не оценено.
Шесть запусков: seeds 42/43/44 для обоих head, 20 эпох × 80 клипов, одинаковые
кадры и разбиение. Результаты ниже относятся к двум dev-видео, использованным
для выбора модели и порогов, и не доказывают обобщение:

- Старый baseline: matched=1, missed=0, extra=1, event F1=0.667, ошибка 4 с.
- Новое усреднение: event F1 0.667/0/0.667; пропуски 0/1/0, лишние события 1/2/1.
- Temporal: event F1=1 во всех трёх запусках, matched=1, missed=0, extra=0;
  ошибка времени 5/4.5/5 с. Поставленный seed 42 имеет ошибку 5 с.

Внутренний допуск сопоставления ±5 с. Улучшение event F1 сопровождается худшей
локализацией относительно старого baseline. При меньшем допуске результат другой.
Модель не распознаёт конкретные типы нарушений и не выдаёт нормативное основание;
нужны дополнительная разметка и проверенный локальный каталог участника 1.
Результат — подсказка человеку, а не юридический вывод и не утверждение о невидимых
операциях АБИС. Корректность JSON не доказывает правильность обнаружений.

## Выборка и получение времени

2 кадра/с, 8 кадров на окно, шаг центров около 0.5 с. Номинальная длина окна 4 с,
охват первого–последнего кадра 3.5 с. Ближайшие PTS с выбором раннего при равенстве
дают на идеальной сетке смещения `[-2,-1.5,-1,-0.5,0,0.5,1,1.5]` с от центра.
На границах кадры повторяются. Максимальный несэмплированный хвост проверенного
набора — 0.4 с; короткие события могут быть пропущены.

Возвращается PTS центра окна с максимальным score внутри срабатывания, затем
ближайшего исходного JPEG-кадра. Это не обученная оценка начала действия.
Порог/подтверждение/объединение сохранены в checkpoint и выбираются только на dev.

## Подготовка и обучение на локальных данных

```powershell
.\.venv\Scripts\python.exe main.py init-weights
.\.venv\Scripts\python.exe main.py prepare --data-dir "C:\local-data\dataset"
.\.venv\Scripts\python.exe main.py train --head-type linear --output artifacts/new_run/linear --seed 42
.\.venv\Scripts\python.exe main.py train --head-type temporal --output artifacts/new_run/temporal --seed 42
.\.venv\Scripts\python.exe main.py compare --baseline artifacts/new_run/linear --temporal artifacts/new_run/temporal --output artifacts/new_run/comparison.json
.\.venv\Scripts\python.exe main.py evaluate --checkpoint artifacts/new_run/selected.pt --split dev --output artifacts/new_run/evaluation.json
```

Разбиение хранится в локальном `artifacts/data/split_registry.json` и сохраняется
при обновлениях. Новые группы по умолчанию идут в train; test необходимо резервировать
до обучения/настройки. Связанные записи объединяются по происхождению; совпадение
сцен без общих кадров не позволяет автоматически доказать независимость.
CSV групп требует явного `--confirm-group-review`; изменения locked dev/test меток
требуют `--accept-label-revisions` и снимают квалификацию прежнего теста.

Скрипты `tools/run_expanded_cycle.py`, `audit_timing.py`, `summarize_expanded.py`
воспроизводят рабочий протокол при наличии локальных манифестов и архивов baseline;
они не заменяют отсутствующие данные фиктивными. Переданный Git checkout содержит
готовые веса для инференса, а не исходный обучающий набор и историю экспериментов.
