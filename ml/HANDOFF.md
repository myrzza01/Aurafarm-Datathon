# Передача ML-модуля и проверка API

Runtime содержит код, локальный checkpoint и каталог нормативных источников.
Исходные Excel, видео, manifest, обучающие кэши и H/J-комментарии для инференса
не нужны. Видео, кадры и описания сцен не передаются внешним сервисам; звук
и идентификация лиц не используются.

## Установка

Основная поставка — полный Git checkout. Из его корня на Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1
```

Установщик использует Python 3.12 и PyTorch 2.7.1/CUDA 12.8; поддержан RTX 5070.
`-Cpu` выбирает CPU-зависимости. `ExecutionPolicy Bypass` действует только в данном
процессе PowerShell. Скрипт запуска создаёт локальный случайный API-ключ,
если его нет, и сохраняет `.env`, исключённый из Git. Браузер ключ не получает.
`ml/setup.ps1` перенаправляет в корневой установщик. Старый CUDA 11.8 lock
описывает прежнее окружение; для текущего приложения используйте корневые скрипты.

Для Linux/macOS команды и переменные приведены в [../README.md](../README.md).
Для полностью изолированной установки заранее подготовьте wheelhouse для
целевой ОС и Python; Windows wheels не подходят Linux. Установка может
скачивать зависимости, инференс после установки работает с локальными файлами.

## Python-контракт

```python
from pathlib import Path
from ml.cashwatch.inference import VideoAnalyzer

analyzer = VideoAnalyzer(checkpoint=Path("ml/weights/reviewed_detector.pt"))
result, diagnostics = analyzer.analyze(Path("C:/local-data/new.mov"), timeout_sec=240)
```

Новая модель совмещает локализацию и 16 предполагаемых типов действий.
Бинарный baseline `weights/detector.pt` сохранён для сравнения; он не классифицирует
действия и не должен получать нормативную ссылку по своему бинарному срабатыванию.
`CASHWATCH_CHECKPOINT` меняет checkpoint серверного адаптера,
`CASHWATCH_DEVICE=cpu` принудительно выбирает CPU.

Ответ содержит `verdict` (`violation` или `no_violation`) и `violations`.
У каждого события:

- `type`, `timecode_sec`, `description`;
- от 1 до 3 `evidence_frames`: исходный JPEG/base64 и `timestamp_sec`;
- обязательный `rule_source`: `provided` с документом или `unmapped` с причиной;
- дополнительные `type_id`, `type_confidence`, `description_source`, `rule_context`.

`type_confidence` — некалиброванный score, не вероятность нарушения и не accuracy.
`description_source=class_template` обозначает шаблон по предполагаемому типу.
Он описывает гипотезу для сопоставления с кадрами, не независимое наблюдение
LLM и не подстановку человеческого H/J-комментария.

Каталог `cashwatch/rules.json` содержит проверенные по официальным текущим
текстам НБРК №231, №14 и АРРФР №53 ссылки, точные пункты, условия и ограничения. Проверка источников:
17.10.2026. Восьми типам сопоставлено условное публичное основание. Для остальных
нужны внутренние правила банка или дополнительный контекст; `unmapped` остаётся
видимым. `related_rule_ids` — контекст, их нельзя выдавать за прямой запрет.
Применимость проверяют отдельно от правильности предсказанного класса.

`no_violation` допустим только при пустом списке событий. Ошибку импорта,
декодирования, неверный результат и таймаут нельзя превращать в `no_violation`.
Не логируйте кадры, ключи, пароли и тексты сцен.

## Backend и полный HTTP-цикл

Обработчик уже подключён через `backend.cashwatch_adapter`. На каждую задачу
создаётся изолированный процесс; загрузка весов входит в срок. Очередь, владельцы
и результаты сохраняются в SQLite. Windows использует файловые блокировки
`msvcrt` и Job Object для завершения дерева процессов, POSIX — `flock` и группы
процессов. Несколько хостов и сетевые файловые системы не поддерживаются.

Методы для жюри:

1. `POST /api/v1/analyze`, multipart-поле `file`, заголовок `X-API-Key` → HTTP 202 и `job_id`.
2. `GET /api/v1/jobs/{job_id}` с тем же ключом → `processing`, затем `done` или `failed`.

Браузер использует `/app/api/v1/...`, пользовательскую HttpOnly-сессию
и `X-UI-Request: 1` при загрузке. Сессия не заменяет ключ на маршрутах жюри.
Полный контракт: [../docs/model-integration.md](../docs/model-integration.md).

`/health` подтверждает настройку, но не качество предсказаний. Полную проверку
делают реальным разрешённым MOV: upload → poll → verdict → тип → JPEG → таймкод →
условия источника. Затем отдельно проверяют отсутствие событий и ошибку модели.

`ANALYSIS_TIMEOUT_SECONDS=270` включает время с начала multipart-запроса,
валидацию, очередь и анализ. Максимальная настройка — 290 секунд, ещё до пяти
секунд оставлено защитному завершению HTTP-запроса. Диагностика модели
`elapsed_sec` не равна полному времени загрузки и получения результата.

`tools/benchmark_http.py` измеряет полный цикл по локальному или частному LAN-адресу.
Он берёт ключ из `CASHWATCH_API_KEY`; ключ должен совпасть с `API_KEY` сервера.
Технический отчёт не содержит сцен и кадров. Публичный URL этим клиентом не
проверяется. Замеры прежней бинарной модели нельзя выдавать за замеры нового checkpoint.

Проверка 17.10.2026: четыре реальных MOV прошли полный цикл на Windows/CUDA
за 5,875–10,5 с; два реальных MOV в изолированном сетевом пространстве WSL/CPU —
за 5,442 и 7,781 с. Публичные API жюри и браузера проверены на искусственном MOV
за 6,125 и 5,953 с. Отчёт о проверках транспорта, JPEG, семантических полей
и локального исполнения: [reviewed_runtime_checks.json](weights/reviewed_runtime_checks.json).
Это техническая проверка, не измерение качества или визуальная проверка браузера.

## Качество и перенос

Данные: 40 уникальных видео, 21 положительное, 19 отрицательных, 22 события,
16 типов действий. H/J подтверждены пользователем; старые статусы бинарных меток
сохраняются отдельно. Большинство типов имеют единственный пример и не имеют
оценки обобщения. Holdout диагностический: независимость сессий и пересечение
с прежним обучением не установлены. Точность на новом ракурсе неизвестна.

Первый диагностический запуск с разбиением 28/6/6 не прошёл проверку обобщения:
на dev и test все отрицательные видео ошибочно положительные, типы — 0/3
верных в размеченных центрах каждой части; полный typed F1=0 и на dev, и на test.
Развёртываемый полный fit после
фиксированных 60 эпох на всех 40 видео имеет только обучающие показатели:
TP=21, FP=8, FN=0, TN=11, video F1=0,84; типы в центрах обучающих событий — 22/22.
Полный детектор → таймкод → тип с допуском ±5 секунд на этих же обучающих видео:
TP=20, FP=18, FN=2, F1=0,667. Точность в размеченных центрах не учитывает лишние
события и пропуски детектора.
У развёртываемых весов нет отдельного неиспользованного теста. Эти цифры не
являются доказательством качества на новых видео или итоговой метрикой жюри.
Отчёты с SHA-256 и происхождением:
[развёрнутые веса](weights/reviewed_report.json),
[диагностический запуск](weights/reviewed_diagnostic_report.json).

При сборке отдельного runtime-пакета включите новый checkpoint, весь код,
используемый инференсом, `rules.json` и лицензии. Сверьте SHA-256 весов и выполните
инференс из распакованного пакета без доступа к исходной книге и видео обучения.
Старый пакет с бинарными весами не является поставкой новой модели.

Для изолированной проверки сети предусмотрен `tools/verify_os_offline.ps1`.
Он требует уже открытый PowerShell администратора и проверяет собственные
временные правила firewall. Скрипт не повышает права самостоятельно. Socket guard
в Python — отдельная техническая проверка и не доказывает изоляцию на уровне ОС.
Автономность полного HTTP-сервиса, браузера и переносимого пакета проверяется
отдельно; наличие локальных весов само по себе этого не доказывает.

Публичный запуск из корня checkout:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-public.ps1
```

Текущий адрес сохраняется в `data/public-url.txt` после успешной внешней проверки
`/health`. URL зависит от работающего на этом ПК сервера и туннеля и меняется после
перезапуска. Остановка: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-public.ps1`.
Проверяйте действующий адрес отдельно от локального API.
