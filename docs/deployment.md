# Запуск приложения и API — зона участника 4

ML-участник меняет модель в `ml/`. Участник 4 отвечает за `backend/`, `frontend/`,
контейнер, проверку API и инструкцию для жюри. Изменения объединяются через Git;
не копируйте целиком папку проекта поверх работы другого участника. Контракт
зафиксирован в [model-integration.md](model-integration.md).

## Что подготовлено

`Dockerfile` собирает CPU-runtime без CUDA и запускает приложение непривилегированным
пользователем. `compose.yaml` поднимает приложение и Caddy, сохраняет базы и результаты
в томе `app_data`, сертификаты — в `caddy_data`. После падения процесса или перезапуска
Docker контейнеры запускаются снова. Docker должен стартовать вместе с сервером.
Healthcheck проверяет HTTP-сервер, но не загрузку модели и не качество распознавания.
Статус unhealthy сам по себе не перезапускает зависший контейнер.

Наружу опубликованы только порты Caddy 80/443. Приложение находится во внутренней
Docker-сети без прямого выхода в интернет. Caddy заменяет клиентские proxy-заголовки;
Uvicorn доверяет заголовкам внутри этой сети. Поэтому HTTPS корректно приводит к
`Secure` у cookie и сохраняется IP для ограничения попыток входа. Не публикуйте
порт приложения 8000 и не запускайте этот CMD напрямую в публичной сети.
Интернет нужен при сборке зависимостей и Caddy для получения/обновления сертификатов.
Это не доказательство автономности всего сервера: её нужно проверять отдельно.

## Локальный запуск на Mac

Нужны Docker Desktop и существующий `.env` с `API_KEY` (или настройка по примеру
ниже). Из корня проекта:

```sh
SITE_ADDRESS=http://localhost docker compose -f compose.yaml -f compose.local.yaml up -d --build
SITE_ADDRESS=http://localhost docker compose -f compose.yaml -f compose.local.yaml ps
```

Приложение: `http://localhost:8080`, Swagger: `http://localhost:8080/docs`.
`compose.local.yaml` заменяет публичные порты на `127.0.0.1:8080`, поэтому сервис
доступен только с этого Mac. Требуется Compose 2.24.4 или новее. Порт 8000 другого
локального процесса не занят; данные Docker находятся в отдельном томе и не копируют
учётные записи или результаты из папки `data/` на Mac. Создайте отдельную тестовую
учётную запись через интерфейс. HTTP-режим не проверяет сертификат и Secure-cookie.

Остановка с сохранением данных:

```sh
SITE_ADDRESS=http://localhost docker compose -f compose.yaml -f compose.local.yaml down
```

Для проверки скриптом задайте ключ в окружении, затем выполните
`python scripts/check_api.py --base-url http://localhost:8080`.
При всех последующих командах локального Compose сохраняйте оба `-f` и
`SITE_ADDRESS=http://localhost`; серверные команды ниже относятся к публичному запуску.

## Подготовка сервера

Нужен Linux-сервер с Docker Engine и Compose v2, локальным диском и DNS-именем,
указывающим на этот сервер. Начальный ориентир для CPU-проверки: 4 vCPU, 8 ГБ RAM,
20 ГБ свободного диска; это ещё не проверенные минимальные требования. Откройте
входящие TCP 80/443. Рекомендуется один экземпляр приложения; очередь не рассчитана
на несколько хостов. GPU в этой конфигурации не используется.

На новом сервере из корня checkout:

```sh
cp .env.example .env
chmod 600 .env
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Впишите сгенерированный ключ в `API_KEY` внутри `.env`, а своё DNS-имя без протокола —
в `SITE_ADDRESS`. Не перезаписывайте существующий `.env` этой командой. Секреты не
передаются как build arguments и не входят в образ. `ANALYZER_CALLABLE` по умолчанию
подключает текущую модель; явно пустое значение отключает анализ. При замене модуля
нужно включить его код и зависимости в образ, затем повторить проверки.

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl --fail https://YOUR_DOMAIN/health
```

Не публикуйте вывод `docker compose config` без `--quiet`: он раскрывает ключ.
Caddy получает сертификат автоматически при корректном DNS и доступных портах.
Для локальной проверки используйте отдельную конфигурацию выше.

## Проверка выпуска

На машине проверки установите корневые `requirements-dev.txt`. Задайте тот же ключ
в окружении без записи в командную строку:

```sh
read -s API_KEY
export API_KEY
python scripts/check_api.py --base-url https://YOUR_DOMAIN
unset API_KEY
```

В zsh используйте `read -s 'API_KEY?API key: '`, вместо bash-команды `read -s API_KEY`.
Скрипт использует только созданное им синтетическое видео, не принимает пути к
реальным записям, не выводит ключ, кадры или описания сцен. Проверяет `/health`,
документацию, ключи обоих методов, неизвестную задачу, пустой/повреждённый/неверный
файл, затем `202 → done` и схему результата с проверкой JPEG. Не следит за
перенаправлениями и не использует прокси окружения. Для удалённых серверов обязателен
HTTPS. Ошибка модели или неправильный ответ завершают проверку с ненулевым кодом.

При намеренно отключённой модели:

```sh
python scripts/check_api.py --base-url https://YOUR_DOMAIN --expect-unavailable
```

Этот режим требует HTTP 503 и **не подтверждает работу анализа**. Обычная проверка
на синтетическом видео проверяет интеграцию, а не точность или нормативные выводы.
Её запуск создаёт одну обычную задачу, которая удаляется по общей политике хранения.

Вручную пройдите в браузере на компьютере и телефоне: регистрация → вход → пример
с явной маркировкой → загрузка разрешённого видео → ожидание → результат → кадры и
таймкоды → выход. Проверьте пропуск анимации, системное уменьшение движения и
клавиатуру. На HTTPS убедитесь в `HttpOnly`, `Secure`, `SameSite=Strict` у `ui_session`.
Не передавайте реальные видео публичному серверу без разрешения команды.

Проверка сохранности: запишите `job_id` завершённой синтетической задачи, выполните
`docker compose restart app` и запросите тот же результат. Он должен сохраниться.
Задача, выполнявшая анализ во время перезапуска, получает `failed`; ожидавшая в
очереди сохраняет первоначальный срок выполнения.

## Обновление и данные

Обновляйте checkout до согласованного коммита и выполняйте `docker compose up -d --build`.
Снова запустите проверку API. Обновление может прервать текущий анализ; делайте его
после завершения активных задач. Для отката верните предыдущий проверенный коммит
и пересоберите образ. Новая модель требует повторной проверки зависимостей,
загрузки весов и реального полного цикла на сервере.

`docker compose down` сохраняет именованные тома; **`down -v` удаляет аккаунты,
сессии, задачи и результаты**. Не удаляйте тома при обычном обновлении. Для резервной
копии согласованного состояния сначала остановите приложение:

```sh
mkdir -p backups
chmod 700 backups
docker compose stop app
docker compose run --rm --no-deps -T --entrypoint python app -c 'import sys,tarfile; t=tarfile.open(fileobj=sys.stdout.buffer, mode="w|gz"); t.add("/app/data", arcname="data"); t.close()' > backups/app-data.tar.gz
chmod 600 backups/app-data.tar.gz
docker compose up -d app
```

Архив содержит приватные данные, включая результаты и хеши сессий. Храните его
только локально у ответственного за сервер. Не добавляйте его в Git и не отправляйте
в чат. Для восстановления нужен остановленный app и восстановление `data/` в тот же
том с владельцем UID/GID 10001; восстановление на реальном сервере ещё не проверено.

## Статус проверки конфигурации

На Mac/ARM64 с Docker Engine 29.8.2 и Compose 5.6.0 проверены сборка CPU-образа,
`pip check`, валидация Caddyfile и запуск через `http://localhost:8080`.
Приложение запускается под UID 10001; `.env` и папка исходных видео в образ не входят.
Проверка через прокси прошла: ключи обоих API-методов, неверные файлы,
синтетический MOV до `done`, схема результата, регистрация/вход/выход,
атрибуты HttpOnly/SameSite cookie в HTTP-режиме, владение задачами и защита POST.
После `restart app` сохранились оба результата (жюри и пользовательский), аккаунт
и активная сессия; временные MOV удалены. Восемь групп runtime-проверок заняли
31,96 секунды суммарно: это не замер отдельного анализа и не оценка точности.
Технические агрегаты без ключей/кадров/описаний сохраняются локально в
`data/deployment-checks/docker-runtime.json` и не входят в Git.

Локальный запуск не означает публикацию. Публичный DNS/HTTPS, Secure-cookie за TLS,
восстановление резервной копии и работа после перезагрузки самого Mac/сервера
пока не проверены. Эти проверки нужны до передачи URL жюри.
Инструкция для жюри: [jury-api.md](jury-api.md).

Официальные справочники: [Docker Compose: порядок запуска](https://docs.docker.com/compose/how-tos/startup-order/),
[Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy),
[Caddy request_body](https://caddyserver.com/docs/caddyfile/directives/request_body).
