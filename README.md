# Aurafarm-Datathon

Forte Vision — интерфейс и API проверки видеозаписей кассовых операций.

Приложение для поиска визуальных признаков возможных нарушений кассовой дисциплины.
Участник 4 отвечает за веб-интерфейс и API. В `references/bee` сохранена анимированная
CSS-пчёлка для главного экрана с исправлением JavaScript.

## Запуск приложения и API

Windows, из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1
```

Установка использует Python 3.12 и PyTorch 2.7.1/CUDA 12.8 для RTX 5070.
Для установки на CPU: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Cpu`.
`ExecutionPolicy Bypass` действует только в запущенном процессе PowerShell,
глобальная политика Windows не изменяется.
`run.ps1` сохраняет случайный `API_KEY` в локальном `.env`, если ключ ещё не задан.
Ключ и `.env` не включаются в Git. Веб-интерфейс: http://127.0.0.1:8000.

macOS/Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export API_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
uvicorn backend.main:create_app --factory --reload
```

Текущая экспериментальная модель `ml/weights/reviewed_detector.pt` совмещает
поиск подозрительных фрагментов и классификацию 16 типов действий. Используется CUDA
при наличии, иначе CPU. Для принудительного CPU: `CASHWATCH_DEVICE=cpu`.
`CASHWATCH_CHECKPOINT` позволяет явно выбрать другой локальный checkpoint.
Исходный бинарный baseline сохранён в `ml/weights/detector.pt`; его происхождение —
в `ml/SOURCE.json`. Бинарный checkpoint не получает выдуманных типов или правил.

Другой Python-модуль можно подключить перед запуском:

```sh
export ANALYZER_CALLABLE="team_model.pipeline:analyze_video"
```

Это пример имени собственного модуля. Функция принимает `pathlib.Path`
и возвращает словарь либо `AnalysisResult`. Контракт локального обработчика:
[docs/model-integration.md](docs/model-integration.md). Без доступных весов и зависимостей
корректное видео получает HTTP 503 без создания задачи. Явно пустой `ANALYZER_CALLABLE`
также отключает анализ. Демонстрация интерфейса доступна независимо от модели.
`/health` показывает `analyzer_configured`: это проверка настройки, а не качества модели.

Главный экран: http://127.0.0.1:8000. Документация API: `/docs`, схема: `/openapi.json`.
Интерфейс принимает один `.mov`, показывает прогресс загрузки, опрашивает статус
задачи и отображает результат, кадры, таймкоды и нормативный источник. Переход
по таймкоду перематывает исходное видео, если его кодек поддерживается браузером.
Ошибка модели отображается как незавершённая проверка. Выводы не подменяются
демонстрационными данными. Пчёлка и её текстуры находятся в проекте; интерфейс
не загружает внешние шрифты или скрипты.

Браузер использует отдельные маршруты `/app/api/v1/…` с HttpOnly SameSite-cookie
и обязательным заголовком для загрузки. Ключ API жюри не передаётся в браузер.
Вход: `/login`, регистрация: `/register`. Главный экран и маршруты браузера требуют
входа в аккаунт. Маршруты `/api/v1/…` для жюри всегда требуют `X-API-Key` и работают
независимо от пользовательской сессии.

Аккаунты и сессии хранятся в `data/auth.sqlite3`, эта папка исключена из Git.
Пароли длиной 12–128 символов сохраняются как scrypt-хеши с отдельной солью.
Сессия действует 8 часов и отзывается при выходе; в базе хранится хеш токена.
При HTTPS cookie получает флаг Secure. Подтверждение email и восстановление пароля
в этой локальной версии не реализованы. Один аккаунт не может читать задачи другого.
После входа или регистрации запускается 3D-туннель из референса Cyberspace Portal:
кривая траектория, частицы и плавающие фрагменты кода. Через примерно 3 секунды
плавно появляется главный экран. Полёт можно пропустить. При настройке уменьшения
движения и при недоступном WebGL вход продолжает работать.
Three.js r128 хранится в `frontend/assets/vendor` вместе с MIT-лицензией;
анимация и формы не требуют внешнего CDN. В `portal-reference.mjs` сохранены
траектория, рендерер фрагментов кода и текстура частиц из предоставленного референса
Matt Cannon; переход адаптирован для входа в приложение.

Кнопка «Посмотреть пример» под формой загрузки открывает экран результатов без
модели и без отправки видео. Доступны два сценария: с событиями и без событий.
В примере используются вымышленные события и локальные SVG-схемы с явной маркировкой.
Эти данные не возвращаются через API и не служат результатом анализа.
На экране можно выбирать событие, переключать кадры и увеличивать их; в окне
просмотра работают клавиши ←, → и Esc. Тот же экран отображает реальные ответы API.
Swagger UI 5.17.14 и его лицензия хранятся в `backend/static/swagger`; `/docs`
использует только локальные JS, CSS и favicon. Внешний валидатор Swagger отключён.
Сам API облачных вызовов не делает. Все зависимости устанавливаются до автономного запуска.
Ключ задаётся через окружение; запуск без него запрещён. Не коммитить ключ.

```sh
curl -X POST http://127.0.0.1:8000/api/v1/analyze \
  -H "X-API-Key: $API_KEY" -F "file=@video.mov"
curl http://127.0.0.1:8000/api/v1/jobs/JOB_ID \
  -H "X-API-Key: $API_KEY"
python -m pytest -q
```

Загрузка возвращает HTTP 202 и `job_id`. Статусы: `processing`, `done`, `failed`.
Обязательные поля результата соответствуют разделу 10 кейса. `rule_source` —
обязательное дополнительное поле каждого события. Локальный каталог
`ml/cashwatch/rules.json` содержит 16 типов и проверенные 17.10.2026 ссылки на
действующие официальные тексты правил НБРК №231, №14 и требований АРРФР №53.
Для восьми типов есть
условно применимое публичное основание с `status=provided`. Для остальных нужны
дополнительный контекст или внутренние правила банка: возвращаются `status=unmapped`
и конкретная причина. Наличие проверенного документа не подтверждает, что все
условия его применения выполнены в данном видео. Интерфейс показывает условия
и ограничения. Отсутствующий или пустой `rule_source` запрещён.

Первичные источники: [кассовые операции №231](https://adilet.zan.kz/rus/docs/V1900019680),
[устройство кассовых помещений №14](https://adilet.zan.kz/rus/docs/V2000020075),
[информационная безопасность №53](https://adilet.zan.kz/rus/docs/V2600038336).

Дополнительные поля `type_id`, `type_confidence`, `description_source` и
`rule_context` показывают предполагаемый тип и условия связи с правилом.
`type_confidence` — некалиброванная оценка модели, не вероятность нарушения и
не измеренная точность. `description_source=class_template` обозначает описание
по предполагаемому классу; сверяйте его с исходным видео и JPEG-кадрами.
Человеческие H/J-заметки не подставляются в ответ как наблюдения модели.

Адаптер `backend/analyzer.py` по умолчанию вызывает `backend.cashwatch_adapter`,
который запускает настоящий `ml.cashwatch.inference.VideoAnalyzer` с локальными весами.
`ANALYZER_CALLABLE` позволяет переопределить обработчик. Импорт, загрузка весов и
анализ выполняются внутри отдельного процесса задачи. `pretrained=False` и локальный
checkpoint исключают скачивание весов при инференсе. Сам модуль использует только
пиксели и временные метки; звук, имя файла и Excel не используются как признаки.
Обработчик возвращает вердикт, события, таймкоды, 1–3 JPEG-кадра в base64
для каждого события и источники правил.
Нельзя возвращать `no_violation` при ошибке модели.

Текущий лимит загрузки — 100 МиБ. Проверяются расширение, размер и непустой файл;
PyAV открывает MOV и декодирует видеопоток целиком в отдельном процессе с лимитом
20 секунд. Допускаются видео до 600 секунд и 16 мегапикселей, максимум 72 000 кадров.
Внешние ссылки QuickTime отключены. Недекодируемое видео получает HTTP 415.
Одновременно проверяется один загружаемый файл на каталог данных; занятость даёт
HTTP 429 с Retry-After. JPEG-доказательства декодируются Pillow: до 2 МиБ и
16 мегапикселей на кадр; полный результат ограничен 24 МиБ и 100 событиями.
Временный файл удаляется после обработки или ошибки загрузки. После аварийного
завершения загрузки координатор удаляет оставшиеся временные файлы старше 10 минут,
если они не принадлежат активной задаче.

Задачи, владельцы и результаты сохраняются в `data/jobs.sqlite3`. При перезапуске
завершённые результаты доступны, очередь продолжается с исходным сроком выполнения,
а прерванный анализ получает `failed` с понятной причиной. Один координатор на
каталог данных ограничивает анализы во всех API workers: `flock` на macOS/Linux,
блокировка файла через `msvcrt` на Windows.
Для каждого видео запускается отдельный процесс; загрузка весов тоже входит в лимит.
Зависший процесс и созданные им дочерние процессы принудительно останавливаются.

Настройки через окружение:

- `ANALYSIS_TIMEOUT_SECONDS=270`: общий бюджет от приёма HTTP-запроса, включая
  multipart-загрузку, проверку файла, очередь и анализ; не более 290 секунд.
  Защитное завершение запроса ограничено дополнительными 5 секундами.
- `ANALYSIS_WORKERS=1`: одновременно от 1 до 4 анализаторов на каталог данных.
- `ANALYSIS_QUEUE_CAPACITY=4`: максимум активных и ожидающих задач вместе;
  переполнение возвращает HTTP 429 с Retry-After.
- `RESULT_RETENTION_SECONDS=86400`: срок хранения завершённых результатов;
  также сохраняются не более 200 последних завершённых задач. Очистка выполняется координатором.

Каталог данных должен быть общим локальным диском API workers. Несколько хостов
и сетевые файловые системы не поддерживаются этой очередью; для них нужна внешняя очередь.
В новом объединённом наборе 40 уникальных видео: 21 положительное, 19 отрицательных,
22 точечных события и 16 типов. Пользователь подтвердил H/J как окончательную
разметку действий; это отдельный факт от сохранённых статусов бинарных меток.
Часть бинарных меток и таймкодов унаследована из исходной разметки и остаётся слабой.
У большинства типов только один пример: для них нет отдельной проверки обобщения.
Диагностический holdout не доказывает независимое качество: связи между сессиями
съёмки и пересечение с прежним обучением пока не установлены. Старые показатели
бинарной модели не являются показателями новой модели.

В первом диагностическом запуске разбиение составляло 28/6/6 видео. На dev и test
модель срабатывала на всех видео: по 3 ложноположительных из 3 отрицательных,
классификация типов в размеченных центрах — 0 из 3 на каждой части,
полный typed F1=0 на обеих частях. Это неуспех проверки обобщения.
Развёртываемая модель затем обучена фиксированные 60 эпох
на всех 40 видео. На этих же обучающих данных: TP=21, FP=8, FN=0, TN=11,
video F1=0,84; тип верен в 22 из 22 размеченных центров. Полная оценка
детектор → таймкод → тип с допуском ±5 секунд на этих же обучающих данных:
TP=20, FP=18, FN=2, F1=0,667. Все эти показатели характеризуют подгонку к обучающему
набору и не заменяют отложенный тест. Параметры, SHA-256 и границы оценки:
[отчёт развёрнутых весов](ml/weights/reviewed_report.json),
[диагностический dev/test](ml/weights/reviewed_diagnostic_report.json).

Техническая проверка 17.10.2026: четыре реальных MOV прошли полный HTTP-цикл
на Windows/Python 3.12/CUDA за 5,875–10,5 с; JPEG и дополнительные семантические
поля валидны. В WSL/Python 3.12/CPU два реальных MOV обработаны за 5,442 и 7,781 с
в отдельном сетевом пространстве с доступным только loopback.
Через публичный HTTPS проверены авторизация, Secure-cookie и оба API на искусственном
MOV: 6,125 с для API жюри и 5,953 с для API браузера.
[Технический отчёт](ml/weights/reviewed_runtime_checks.json) подтверждает
работоспособность транспорта и локального анализа; точность распознавания
и отрисовка интерфейса в браузере оцениваются отдельно.

## Публичный запуск на этом ПК

После установки остановите обычный `run.ps1`, затем запустите:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-public.ps1
```

Скрипт запускает локальный backend и временный HTTPS-туннель, проверяет публичный
`/health` и сохраняет текущий адрес в `data/public-url.txt`, состояние — в
`data/public-run.json`. Адрес меняется после перезапуска туннеля. Этот ПК должен
оставаться включённым и подключённым к интернету. Остановка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-public.ps1
```

## Следующие этапы

1. Дополнить редкие типы, согласовать группы исходных съёмок и независимо оценить качество.
2. Передать внутренние правила банка для оставшихся типов и проверить применимость публичных норм.
3. Проверить автономность переносимой поставки и сохранять доступность публичного адреса для жюри.

Доступность публичного адреса проверяют после каждого запуска на этом ПК.

Дополнительные функции — история, экспорт, пакетная загрузка и пользовательские
аккаунты — в кейсе не обязательны.
