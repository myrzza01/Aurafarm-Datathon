## Собираем картину по блокам

Загрузите запись кассовой операции в формате MOV, дождитесь анализа и изучите найденные фрагменты с таймкодами и JPEG-кадрами. Для событий отображаются предполагаемый тип действия, нормативный источник и условия его применения.

Бордовая палитра Forte, блочная эстетика Minecraft и пчёлка-маскот объединяют оформление проекта. В приложении есть анимированный 3D-переход после входа и интерактивный просмотр доказательств. Баннер выше — авторская пиксельная иллюстрация, а не скриншот приложения.

> **Экспериментальный прототип.** Найденное событие требует проверки человеком. Модель не устанавливает факт нарушения; независимое качество текущих весов пока не подтверждено.

## Быстрый старт

Команды выполняются из корня репозитория. Для Python-запуска нужен **Python 3.12**; для контейнера — запущенный **Docker Desktop / Docker Engine**. Зависимости устанавливаются до автономного инференса.

### Windows · CPU

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Cpu
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1
```

Для **RTX 5070 / CUDA 12.8** запустите установку без `-Cpu`. Скрипт устанавливает PyTorch 2.7.1 и создаёт `.venv`. `run.ps1` сохраняет случайный `API_KEY` в локальном `.env`, если ключ ещё не задан. `ExecutionPolicy Bypass` действует только в текущем процессе.

### macOS / Linux

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export API_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
uvicorn backend.main:create_app --factory --reload
```

| После запуска | Адрес |
| :--- | :--- |
| Приложение / вход | http://127.0.0.1:8000 |
| Swagger UI | http://127.0.0.1:8000/docs |
| Состояние сервера | http://127.0.0.1:8000/health |

Создайте аккаунт через `/register`. По умолчанию используются поставляемые локальные веса `ml/weights/event_localizer_detector.pt`; для анализа нужны ML-зависимости. `CASHWATCH_CHECKPOINT` позволяет выбрать другой checkpoint. Если эта переменная уже задана в окружении или `.env`, она переопределяет выбор по умолчанию. Без доступного анализатора корректное видео получает **HTTP 503**; демонстрация остаётся доступна. `analyzer_configured` в `/health` показывает настройку, а не качество модели.

Модель использует пиксели и временные метки. Звук, имя файла и Excel-разметка не входят во входные признаки. Видео и кадры не отправляются внешним AI-сервисам. Ошибка анализа получает статус `failed` и не подменяется выводом об отсутствии нарушений.

## API

Маршруты жюри требуют `X-API-Key`. Браузер использует отдельные `/app/api/v1/…` с пользовательской сессией; ключ жюри ему не передаётся.

```sh
# Bash: API_KEY должен быть задан в окружении
curl -X POST http://127.0.0.1:8000/api/v1/analyze \
  -H "X-API-Key: $API_KEY" -F "file=@video.mov"

curl http://127.0.0.1:8000/api/v1/jobs/JOB_ID \
  -H "X-API-Key: $API_KEY"
```

Загрузка возвращает **HTTP 202** и `job_id`. Подставьте его вместо `JOB_ID` и опрашивайте задачу: `processing` → `done` или `failed`. Контракт — в [памятке для жюри](docs/jury-api.md), интерактивная схема — в `/docs`.

| Ограничение | По умолчанию |
| :--- | :--- |
| Файл / длительность видео | До 100 МиБ / 600 секунд |
| Общий бюджет запроса | 270 секунд, включая загрузку и очередь |
| Параллельные анализаторы | 1 |
| Активные и ожидающие задачи вместе | 4 |
| Хранение завершённых результатов | 24 часа, не более 200 последних задач |

Недекодируемое видео получает HTTP 415, переполнение — HTTP 429 с `Retry-After`. Настройки и остальные лимиты — в [техническом обзоре](docs/technical-overview.md).

## Что важно знать о модели

Текущие веса `event_localizer_detector.pt` добавляют обученный локализатор центров событий к `hard_negative_detector.pt`. Набор содержит **40 уникальных видео**: 21 с положительной и 19 с отрицательной меткой, 22 размеченных события и 16 типов. Большинство типов представлены одним примером.

**Проверка 18.10.2026:** все 42 файла заново обработаны через `VideoAnalyzer` с декодированием, моделью и извлечением JPEG; суммарное время анализа — **18,422 с**. Это прямой вызов модели, не замер HTTP-цикла. Точные копии учтены один раз в основных метриках.

| Метрика на 40 уникальных видео | Результат |
| :--- | ---: |
| Accuracy «нарушение / норма» | **100% — 40/40** |
| Полностью верные видео: итог, все события и время ±1 с, без лишних сигналов | **97,5% — 39/40** |
| Precision / Recall событий: правильный тип и время ±1 с | **95,7% / 100%** |
| F1 событий: правильный тип и время ±1 с | **97,8%** |

Из 23 предсказанных событий **22 совпали по типу и времени, 1 лишнее, пропусков нет**. Остался дополнительный сигнал на **Х-13, 58 с**. Все 22 совпавших центра точно совпали с разметкой; этот результат относится к известным обучающим видео. Полностью верны 20/21 положительных и 19/19 отрицательных видео.

Локализатор обучался 25 эпох, 500 обновлений, 599 201 параметр; все 256 исходных тензоров энкодера, нормализации и голов классификации сохранены побитно. Gaussian-цель с σ=0,75 с учит близости к размеченному центру, а не вероятности нарушения или нормы. Проверка сохранила все прежние 19 верных событий при ±1 с, 20 при ±5 с, 21 временное совпадение при ±5 с, 33 полностью верных видео при ±5 с и все 40 бинарных решений.

**Все видео участвовали в обучении и выборе текущих весов.** Это согласие с имеющейся разметкой, часть бинарных меток и таймкодов остаётся слабой. Независимая точность на новых съёмках ещё не установлена. [Полный PDF-отчёт](docs/reports/forte-vision-ml-audit-one-second-2026-10-18.pdf) содержит все видео и расхождения; [JSON](ml/weights/event_localizer_report.json) — метрики и контрольные суммы.

У предыдущего `hard_negative_detector.pt` precision / recall / F1 событий составляли **70,4% / 86,4% / 77,6% при ±1 с** и **74,1% / 90,9% / 81,6% при ±5 с**. Его HTTP-проверка 42 файлов со средним временем 7,097 с на файл относится только к этой предыдущей версии: [исторический отчёт](ml/weights/hard_negative_report.json).

История экспериментов: у прежнего `reviewed_detector.pt` video F1 = 0,84 и event/type F1 = 0,667 на обучающем наборе; первый диагностический запуск дал typed F1 = 0 на dev и test. Это результаты **прежних весов**, сохранённые в [историческом отчёте](ml/weights/reviewed_report.json) и [исторической диагностике dev/test](ml/weights/reviewed_diagnostic_report.json).

`type_confidence` — некалиброванная оценка модели, а не вероятность нарушения. Для восьми типов есть условно применимые публичные основания; остальные требуют контекста или внутренних правил банка. Подробности: [ML-модуль](ml/README.md), [конфигурация текущих весов](ml/weights/event_localizer_config.json).

<summary><b>Если что-то пошло не так</b></summary>

| Симптом | Что проверить |
